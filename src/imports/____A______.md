# 아이디어 A 압축 기획서

## 0. 문제 재정의 — "우리가 겪은 불편함" 기준

청년·국민 대상 지원금·혜택은 실제로 존재하지만, 정보가 여러 기관 사이트에 흩어져 있어 SNS나 유튜브에서 우연히 보고서야 "이런 게 있었구나" 알게 되는 경우가 많다. 정작 신청 마감이 임박했거나 이미 지나버린 뒤에 알게 되는 것도 문제다. 기존 정부 서비스는 크게 두 갈래로 나뉘는데, ①온통청년·청년몽땅정보통 같은 **목록 나열형**(카테고리별로 정책을 죽 보여줄 뿐 내가 해당되는지는 직접 읽고 판단해야 함)과 ②보조금24·혜택알리미 같은 **완전 인증 기반 개인맞춤형**(주민등록번호 연계, 공동인증서 필요)이다. 그 사이, "회원가입이나 실명인증 없이도 간단한 정보만 입력하면 AI가 나에게 맞는 걸 걸러서 알려주는" 영역은 비어 있다.

---

## 1. AI 필연성 4문항 체크

| 질문 | 답 |
|---|---|
| AI 없이도 성립하는가? | **아니오** — 정책 데이터의 "지원대상" 항목은 "만 19~34세 미취업 청년, 중위소득 120% 이하" 같은 비정형 조건문으로 되어 있어 단순 키워드 필터로는 매칭이 부정확함. 이 조건문을 해석해서 사용자 상황과 대조하고, 왜 해당되는지 설명까지 생성하는 건 AI 없이 불가 |
| 이틀 내 핵심기능 1개로 데모되는가? | **예** — "간단 프로필 입력 → 매칭된 정책 목록+설명" 하나만 완성해도 데모 성립 |
| 외부 API 무료·즉시 발급 가능한가? | **부분적 리스크** — 보조금24 오픈API(공공데이터포털)는 표준 프로세스라 비교적 빠름. 온통청년 청년정책 API는 자체 사이트에서 "담당자 심사 후 승인"이라 시간이 걸릴 수 있어 **오늘 중 신청 필수** |
| 발표에서 "우와" 포인트 있는가? | **예** — 심사위원이 자기 나이·지역만 입력해서 "숨어있던 내 지원금"이 나오는 라이브 데모 |

**해당하는 AI 필연성 패턴**: 주로 **비정형→정형 변환**(자격요건 텍스트를 구조화해 매칭 가능한 형태로) + **개인화 생성**(사용자 프로필에 맞춰 "왜 당신에게 해당하는지" 자연어 설명 생성)

## 2. 타 서비스와의 차이점

| | 온통청년·청년몽땅정보통(정부) | 청년지원정책매뉴얼 등 민간 앱 | 보조금24·혜택알리미(정부) | **우리** |
|---|---|---|---|---|
| 정보 제공 방식 | 카테고리별 목록 나열 | 카테고리별 목록 나열 | 개인 자격정보 실시간 연동 맞춤 안내 | AI가 비정형 조건 해석 후 매칭 |
| 개인화 여부 | 없음(직접 읽고 판단) | 없음 | 있음(정교함) | 있음(간단 입력만으로) |
| 인증 요구 | 로그인 정도 | 없음 | **주민등록번호 연계 + 공동/금융인증서 필수** | 없음(비회원, 간단 프로필만) |
| 매칭 근거 설명 | 없음 | 없음 | 수급 여부만 표시, 이유 설명 없음 | **AI가 왜 해당되는지 자연어로 설명** |
| 진입장벽 | 낮음 | 낮음 | **높음**(본인인증 절차) | 낮음 |

**정리하면**: 정부 공식 서비스는 "완전히 정확하지만 인증 장벽이 높은" 쪽(보조금24)과 "장벽은 낮지만 직접 다 읽어야 하는" 쪽(온통청년)으로 양극화되어 있다. 우리는 그 중간 — **인증 없이 가볍게 입력만 해도 AI가 대신 걸러서 이유까지 설명해주는** 지점을 노린다. 다만 보조금24 수준의 정확도(실제 수급 이력 대조)는 우리가 따라갈 수 없으므로, "완전히 정확한 자격 판정"이 아니라 "**우선 이런 게 있다는 걸 놓치지 않게 알려주는** 1차 스크리닝 서비스"로 포지셔닝을 명확히 해야 발표 때 방어가 된다.

> ⚠️ 발표 때 "보조금24가 이미 있는데 왜 필요하냐"는 질문이 나올 가능성이 높음. "정확한 수급 판정은 보조금24가, 인증 없이 가볍게 훑어보고 놓친 걸 찾는 건 우리가"라는 역할 분리로 답변 준비할 것.

## 3. 데이터 소스

| 데이터 | 제공처 | 제공 정보 | 발급 난이도 |
|---|---|---|---|
| 한국고용정보원_온통청년_청년정책API | 공공데이터포털 | 정책명, 정책설명, 지원대상, 신청기간, 주관기관 등 | 공공데이터포털 표준 신청, 보통 빠름 |
| 대한민국 공공서비스(혜택) 정보(보조금24) 오픈API | 공공데이터포털(행정안전부) | 중앙부처·지자체 수혜서비스 목록, 지원대상조건 텍스트, 신청기간 | 공공데이터포털 표준 신청, 즉시~수일 |
| (선택, 스코프 제외 권장) 서울시 등 지자체 개별 API | 각 지자체 | 지역 한정 청년정책 | 지자체마다 상이, 시간 부족 시 배제 |

두 API 모두 "지원대상"이 자유 텍스트로 되어 있어, 원시 데이터 자체는 이미 공개되어 있지만 **개인 상황과 매칭하는 해석 단계**가 비어 있다는 게 핵심 — 여기가 AI가 들어갈 자리다.

## 4. MVP 흐름

```
① 사용자가 간단한 프로필 입력 (나이, 거주지역, 현재 상태: 구직/재직/창업준비 등 — 인증 없음)
        ↓
② 서버가 병렬로 2개 API 조회: 온통청년 정책API + 보조금24 오픈API
        ↓
③ AI가 각 정책의 "지원대상" 비정형 텍스트를 해석해 사용자 프로필과 매칭 스코어링
        ↓
④ 매칭된 정책을 마감임박순으로 정렬
        ↓
⑤ Claude API가 "왜 당신에게 해당하는지"를 정책별로 짧은 자연어 요약 생성 → 카드 형태로 표시
```

## 5. 세부 기능 범위 판단

| 기능 | 판단 | 이유 |
|---|---|---|
| 프로필 입력 → 정책 매칭 + 설명 | **MVP 핵심 포함** | 위 흐름의 본체, AI 필연성이 여기 집중됨 |
| 마감임박순 정렬 | **MVP 포함** | 별도 인프라 없이 정렬 로직만 추가하면 되므로 비용 낮음, "놓치기 전에 알려준다"는 핵심 메시지와 직결 |
| 마감 임박 푸시 알림 / 캘린더 연동 | **비권장(스트레치 골로만 언급)** | 알림 발송 인프라(스케줄러, 메시징) 구축은 이틀 내 부담이 큼. 발표에서는 "향후 확장 계획"으로만 언급 |
| 개인 자격정보 실시간 연동(보조금24 수준 정확도) | **제외** | 주민등록번호 연계·본인인증 절차가 필요해 해커톤 스코프 밖. 애초에 보조금24와 역할을 분리한 포지셔닝이므로 불필요 |

**결론**: 프로필 입력 → AI 매칭+설명 → 마감임박순 정렬까지가 MVP 전부. 알림 기능은 "이런 방향으로 확장할 수 있다"는 발표용 로드맵으로만 남긴다.
